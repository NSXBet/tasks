Task → review

One record, shaped like a GitHub PR: the agent works in a worktree, the branch is the evidence, commits and diff are derived — never handed over file by file. Review is diff, copied from hunk and reimplemented as tk's own component, in the terminal and on the web.

It gives the user the experience of a pull request — but the PR experience is not what defines it. The task→review flow is. R49

tk work → tk finish → tk review harness registry: omp first additive — nothing replaced
+

NEW views are a plus — they do not replace anything. The task view, artifact view and diff view are additional views in the web and TUI. Existing views — list, kanban, tk show, issues, epics, graph — stay exactly as they are. R47

The branch with its commits, the diff computed from that branch, the session that produced it, two doors into review. The agent line renders from the harness registry — omp first, codex and cursor next; adding a harness type is an entry, not a patch. Every surface that shows a task carries the same two doors. The agent supplies nothing — there is no file list to hand over. R02 · R04 · R05 · R07 · R08 · R09 · R10 · R16 · R50 · R51

§2 · THE THREE VIEWS — TUI + WEB, ADDITIVE

Designed on the record, built twice

Around the record: three views, each rendered below as it lands in the web and the TUI. Left: the working tasks. Middle: the task, front and center — artifacts as the main column, sessions in the side rail. The worktree stays visible even on narrow views; changes opens the diff modal; the full diff view adds evidence images. Every file commentable, line by line or whole file, like GitHub.

§3 · THE DIFF VIEW — COPIED FROM HUNK

Exactly hunk, copied — the terminal diff viewer

Hunk (modem-dev/hunk) is a review-first terminal diff viewer built on OpenTUI and Pierre diffs. tk copies it and reimplements it as packages/review — swapped inputs, outputs and storage, same rendering stack. Below: the diff view, copied from hunk — files pane, unified/split diff, hunk headers, line numbers, agent-context notes, review notes with replies — full page and modal. R40 R41 R44 R45 R46

CLI

tk diff TK-142 opens the diff view on the task's diff. tk review TK-142 opens the full review surface.

TUI

“open diff” in the task view, the changes rail or a file row in it, or an EDIT block in a session — all open the diff view.

WEB

click any diff surface → the diff view as a modal; ⤢ expands to the full page. Same store the TUI writes.

§4 · ONE MODULE, MANY SURFACES

Reusable by construction

Git diff shows up in many places — so the diff component is one module, vendored once and rendered everywhere. Every surface below is the same packages/review component with the same three behaviors: live, editable, commentable. R48

packages/review

slice copied from hunk — changeset, review document, watch controller, reducer. Renderer: OpenTUI (terminal) · @pierre/diffs (web, ./react + ./edit).
