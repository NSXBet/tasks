Decision IDs: D-01..D-05 as numbered in 10-01-PLAN.md `<objective>`. This plan implements D-02 exactly as the spec's
loop table describes `tk watch`: `--until`, `--drain`, `--follow`, per-subscriber cursors, and many watchers at once.

**As an** agent in any harness (codex, cursor, a plain shell), **I want to** run `tk watch <id> --until
"status=approved|rejected"` as a blocking tool call and `tk watch --drain` at session start, **so that** I wait for
review without polling and without a daemon, and nothing that happened while I slept is lost.

Purpose: ROADMAP Phase 10 SC-1 ("`tk watch <id…>` reads it with per-subscriber cursors and `--until/--drain/--follow`,
so many agents watch simultaneously via tool calling and CLI") and SC-3 (agents pick up comments and approvals).
WIRE-01, WIRE-03.

Mode semantics (spec `loop.wire.modes`; behavior that the spec does not fix is settled here at Claude's discretion):
- Subscriber name: `--as <name>` → `session:${TK_SESSION}` → `cli:${actor}`.
- Starting point: the stored cursor if present. Otherwise `--drain` and `--until` start at 0 (full history, filtered),
  and `--follow` starts at the log end. `--from <seq>` overrides. `--peek` never writes the cursor.
- `--until` returns the first match past the starting point. If none, it sleeps on the file (`waitForAppend`) until a
  match or the timeout (default 30m, accepts `90s` / `30m` / `2h` / ms). On match it writes cursor = that event's seq.
  Status precheck: when the query has `status=` and task ids are given (positional or `task=`), it reads those tasks
  first. If any is already in a listed status, it prints a synthesized `task.status` line (`data.current: true`,
  `seq` = log end) and exits 0. This protects an agent that starts watching after the reviewer already acted. The
  precheck also stops a stale approval from an earlier round from matching after the task has moved on.
- Output: human one-liners by default (`formatEventLine`: `#<seq> <ts hh:mm:ss> <task> <type> <summary>`, where summary
  is `from → to`, `author: body` truncated to 200 chars, or `fields`). `--json` prints the raw log line envelope.
- Exit codes: 0 match / drained / follow ended cleanly; 124 until-timeout; 1 invalid query (`invalid watch query: …`)
  or unknown task id (`issue not found: <id>`).

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-19 | Denial of service | `--until` with no timeout | medium | mitigate | default timeout 30m; exits 124; `--follow` ends on stdin EOF/SIGTERM so harness-held calls do not leak processes |
| T-10-20 | Spoofing | `--as` another agent's name | low | accept | cursors are advisory read positions in a local, single-user workspace; worst case is a re-delivered or skipped event for that name |
| T-10-21 | Tampering | user text in human output | low | mitigate | `formatEventLine` strips control characters / ANSI escapes from body/title before printing |
