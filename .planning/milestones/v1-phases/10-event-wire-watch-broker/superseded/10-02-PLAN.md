**As an** agent running in a plain shell (codex, cursor, any harness), **I want to** run `tk watch <id>` and receive
that task's status verdicts, comments and sent review cards on stdout, **so that** I can wait for review without
polling and act on the event without a second read.

sent batches ride the stream). WIRE-01, WIRE-03.
Output: richer watch events, the CLI transport, a CLI e2e test, the protocol bump, rpc.md + overview docs.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell argv → `tk watch` | ids typed by a user or an agent |
| stored comment/card text → event frames | user-authored bodies now travel on the stream to agents and terminals |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-05 | Tampering | `tk watch <id…>` argv | low | mitigate | Every id is looked up before subscribing; an unknown id fails loudly instead of silently watching nothing (hallucinated ids surface). |
| T-10-06 | Denial of service | event bodies | medium | mitigate | Bodies truncated at `MAX_EVENT_BODY` (4000) chars; per-subscriber cap per tick from 10-01. |
| T-10-07 | Spoofing | frames printed to terminals | low | accept | NDJSON is JSON-encoded (control characters escaped by `JSON.stringify`); human renderers sanitize in 10-03/10-04/10-05. |
| T-10-08 | Repudiation | contract drift | low | mitigate | VERBS_VERSION bump makes an old daemon fail hello loudly (`ContractMismatch`) → `tk watch` falls back in-process with a stderr reason. |
</threat_model>
