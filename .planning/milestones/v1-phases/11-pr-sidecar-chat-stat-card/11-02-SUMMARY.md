# Phase 11 Plan 02: `tk pr` create / sync / show (PR-01) Summary

**A task now has at most one PR, mirrored on the record as `metadata.pr = {number, url, state}`. `tk pr create <id>` pushes `tk/<id>` to `origin` through @tasks/git. It then refreshes the recorded open PR, adopts an open PR already on GitHub for the branch, or runs `gh pr create`. `tk pr sync <id>` is the only remote read (one `gh pr view`). `tk pr <id>` reads the local mirror with zero gh calls. All gh runs through `packages/surface/src/gh.ts`, and tests use a fake `gh` on PATH with a local bare repo as origin.**

**Commits withheld per AGENTS.md** (conservative profile: no git commit or push). All changes are uncommitted in the main tree. STATE.md and ROADMAP.md were not updated, per the orchestrator override. The fixture's executable bit is set on disk (0755). Whoever commits should make sure git records it as 100755 (`git update-index --chmod=+x packages/cli/test/fixtures/gh` if needed). The tests chmod their own copy either way.

## What changed

### Task 1 (tracer): create → push → fake gh → record
- `gitPushBranch` sits next to `gitCreateBranch`/`gitDeleteBranch` and returns the same `GitOutcome` shape.
- `pr-record.ts` (domain, pure) provides the enum, validation, the narrowing read and `prLine`.
- `gh.ts` resolves the binary with `ghBinary()` (`TK_GH` or `gh`). `runGh` maps errors (127 → not found; non-zero → `gh <a0> <a1> failed: <first stderr line>`). It also holds `ghPrView`, `ghPrListOpenForHead` and `ghPrCreate` (last non-empty stdout line is the URL, then view). Arguments are argv arrays only.
- `pr.ts`: `prCreate` reads the issue in a short transaction, then checks the branch (`tk pr create needs a worked task — run tk work <id> first`). A closed or merged record refuses (`<id> already has PR #n (<state>) — one PR per task; run tk pr sync <id>`). Then it pushes; a failure gives `git push failed: …` before any gh call. Next comes refresh, adopt or create. Create uses base = `gitDefaultBranch` ?? `main`, and the body is `tk: <id>` + first description paragraph + `statCardLine`. Last, `reportStampFor` runs and one short re-reading save writes `pr` (+ `report`).
- CLI: `pr` added to `writers`, plus `CommandService.pr` and a `command === "pr"` dispatch. JSON is `{id, op, pr}` (create/sync) or `{id, pr}` (show). `formatPr` in presentation.ts. HUMAN_HELP and the full HELP gained the lines, so `tk pr -h` works.

### Task 2: idempotency, sync, mirror, failures
- `prSync`: requires a record (`no PR on <id> — run tk pr create <id>`), then one `ghPrView`, the report restamp and one save. `prShow` reads only.
- No timers, loops or retries: `grep -rn "setInterval\|setTimeout" packages/surface/src/gh.ts packages/surface/src/operations/pr.ts` returns nothing.

### Contract text and docs (orchestrator brief)
- One sentence added after the `tk changes` sentence in the template and both shipped SKILL.md copies, and one clause added to PRIME's review line: "One PR per task: `tk pr create <id>` pushes the branch and opens it via gh (recorded on the task); `tk pr sync <id>` pulls its state — only when asked, never polled." Then `bun packages/cli/src/tk.ts skill install --force` and `bun packages/cli/src/tk.ts onboard install` were re-run at the repo root. The `.agents` copy is byte-identical to the CLI copy, and AGENTS.md was regenerated. `contract.test.ts` CONTRACT gained `"tk pr create <id>"`.
- overview.md has a new `### Pull requests` section. architecture.md has a new `### PR sidecar path` section, and the "planned to restamp" wording is replaced. integrations.md has a new "GitHub CLI (`gh`, PR sidecar)" entry.
