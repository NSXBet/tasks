<objective>
Close the verified gaps in merge-aware worktree removal (LC-01), close-time auto-prune reporting (LC-02), and `tk worktree clean` (LC-03). Most of the machinery already exists and is green (40 tests across `packages/git/test/prune.test.ts`, `packages/cli/test/work.test.ts`, `packages/surface/test/prune.test.ts`, `packages/workspace/test/workspace.test.ts`); this plan fixes only what was verified missing or wrong:

1. `gitIsMergedToBase` treats any `git cherry` output as "unmerged", so a rebase-merged branch is never prunable (probe: `git cherry main tk/a` → `- 09da92…`, `merge-base --is-ancestor` → 1, `git branch -d` → "not fully merged"). The prune path doesn't call it at all — it uses a private `mergedIntoBaseLine`.
2. `tk worktree remove` checks dirty/unpushed/stash only — no merge check (spec §7: "`tk worktree remove` and every prune path refuse while the branch is unmerged").
3. `pruneClosedWorktree` dry-run returns `prunable: true` for a task whose worktree and branch are already gone, so `tk worktree clean` lists already-pruned tasks as eligible forever; `--yes` prunes in the candidate loop and then calls prune a second time; it never records `metadata.worktreePruned`; `--dry-run` (the spec's verify-item spelling) isn't recognized.
4. Human `tk close` output says nothing about the prune outcome (only the `--json` metadata carries `worktreePruned`).

Purpose: tk replaces gw's `end`/`clean` safety. Removal is merge-aware everywhere, and the close tells the user what happened to the worktree.
Output: patched `prune.ts`, `tk.ts` worktree remove/clean + close note, lifecycle tests, docs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git refs → deletion decision | Branch/worktree deletion is decided from git state (ancestry, cherry output); a wrong "merged" verdict destroys unmerged work |
| `.tasks/config.json` → shell | `worktree.preEnd` is a committed shell string executed before removal |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-01 | Tampering | prune.ts force branch delete | high | mitigate | `-D` only reached after `gitIsMergedToBase` returned true for that exact branch in the same call; cherry check requires zero `+` lines; any git error in a rule counts as not-merged; tests cover partially-merged (one `+` line) → refused |
| T-06-02 | Tampering | tk worktree remove | medium | mitigate | merge guard added before removal; `--force` remains the only bypass and is explicit; unresolvable base → refuse unless `--force` |
