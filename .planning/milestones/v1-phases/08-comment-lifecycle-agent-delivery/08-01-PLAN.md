<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell argv → CLI | comment ids and issue ids typed by a user or an agent |
| stored comment text → terminal | bodies, authors and locations written by TUI/web/agents are printed by `tk comments` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `tk comments <op>` argv | medium | mitigate | Ids are only compared against stored thread ids (no paths, no shell); unknown cid fails before any write; extra positionals on resolve/dismiss/reopen fail instead of acting on the first; `send` validates every named cid first. |
| T-08-02 | Spoofing | terminal output of comment bodies | low | mitigate | Rows go through `formatReviewCard` / `safeFirstLine`, which strip control characters (03-05 T-03-08); the send listing reuses `safeFirstLine` for location, author and body. |
| T-08-03 | Repudiation | lifecycle moves | low | mitigate | Every move records `actor` (the CLI's resolved actor) and `at` in `metadata.reviewCommentLog`; tests assert the actor is stamped. |
| T-08-04 | Denial of service | `send` with nothing open | low | accept | Returns an empty batch without writing; no summary comment is added. |
</threat_model>
