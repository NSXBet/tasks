<objective>
Gap closure (09-VERIFICATION.md gap 3, tk task `tasks-n5xi`): untracked new files must appear in the live changeset in both shapes.

**As a** reviewer, **I want** a file the agent created but never `git add`ed to show up in CHANGES, the diff, the minimap and the counts, **so that** the live task view shows all of the work in the worktree.

Purpose: VIEW-02 / R67 "changes reads the worktree live". The fix lands once, in the typed git adapter's working-tree patch, so TUI `source.ts`/`live.ts` and web `review.ts` all get it.
Output: extended `gitDiffPatch`, two new enumerated single-invocation helpers, adapter + TUI + web tests, the architecture.md contract update.

Approach (chosen over a temp-index `add -N`): `git ls-files --others --exclude-standard -z` lists untracked paths and `git diff --no-index -- /dev/null <path>` renders each as a new-file patch. Both are read-only on the repo, so the user's index can't be touched. A temp `GIT_INDEX_FILE` copy would need env support in `ProcessRunner` and a file copy of the index; that is more moving parts for the same output.

Verified state: `gitDiffPatch` (packages/git/src/commands.ts ~L93) is one `git diff --patch [--full-index] [--unified=n] --end-of-options <from>` call through the `git()` helper, and that helper returns null on any non-zero exit. Its callers in working-tree form are `packages/tui/src/review/source.ts:92`, `packages/tui/src/review/live.ts:31` (the watch signature) and `packages/web/src/review.ts:125`. Everything downstream (`patchFileStats`, `changesTree`, `minimapBars`, TUI `finish()`) derives from that patch. The TUI watch plan covers the whole worktree tree, and the web server runs a native recursive `fs.watch` per worktree. So a file creation already fires a refresh, and only the patch is missing the file. The module header says "Each function wraps exactly one git invocation". Keep that rule: add one helper per invocation and have `gitDiffPatch` compose them.
</objective>
