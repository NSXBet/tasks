    - `hunkEditRange(file, 0)` on a parsed patch whose hunk is `@@ -3,2 +3,4 @@` → `{ start: 3, count: 4 }`. An out-of-range index → null. A binary or deleted file (no new side) → null.
    - `guardWorktreePath(root, "src/a.ts")` → ok, with an absolutePath under `realpath(root)`. `"../x"`, `"/etc/passwd"`, `""` and `"a\0b"` → `{ ok: false, kind: "escape" }`. A path through a symlinked dir `root/link → /tmp/outside` → `escape`.
    - `readHunkRegion(root, "src/a.ts", { start: 3, count: 2 })` → `{ text: "<line3>\n<line4>", eol: "\n" }`. Lines are 1-based. count 0 → empty text (an insertion point).
    - `applyHunkEdit(root, "src/a.ts", range, original, next)` replaces exactly lines `start..start+count-1` with `next` (split on `\n`), keeps every other line byte-for-byte, keeps the file's trailing-newline state and CRLF line endings, and returns `{ ok: true }`.
    - `applyHunkEdit` when the on-disk region no longer equals `original` → `{ ok: false, kind: "stale" }`, and the file is unchanged.
    - `applyHunkEdit` on a missing file → `{ ok: false, kind: "missing" }`.
  </behavior>
  <action>
    Per D-03 (the write is guarded to stay inside the worktree; mirror the web guard).
    - New `packages/tui/src/review/edit.ts`. It does not import the web package; its only imports are

      - `hunkEditRange(file: HunkDiffFile, hunkIndex: number): { start: number; count: number } | null`. Read
        `file.metadata.hunks[hunkIndex]` → `{ start: additionStart, count: additionCount }`. Return null when the

        `resolve(realpath(root), relativePath)` must start with `realpath(root) + sep`. Also `realpath` the nearest
        existing ancestor of the target and re-check the prefix, which closes the symlinked-dir escape the web guard
        does not check.
      - `readHunkRegion(root, relativePath, range)` → `{ ok: true, text, eol } | error`. Detect `\r\n` vs `\n` from

      - `applyHunkEdit(root, relativePath, range, original, next)`:

        2. Re-read the file and refuse with `stale` when the region differs from `original`.

        4. Write with the detected eol, keeping the trailing-newline state.
        5. Return the outcome. It never throws; IO errors map to `missing`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewer keystrokes → worktree filesystem | Buffer text is written to a file whose path comes from the diff (patch file names) |
| patch file names → path resolution | The file path in a diff is attacker-influenced: an agent can commit any path, including symlinks |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03 | Tampering / Elevation | edit.ts guardWorktreePath + applyHunkEdit | high | mitigate | Reject empty, absolute and NUL paths. Prefix-check against `realpath(root)`, then realpath the nearest existing ancestor and re-check, which blocks `..` and symlinked-dir escapes. The root is `ReviewSource.cwd` (the worktree root from `gitWorktreeList`), never a user-entered path. Unit-tested in review-edit.test.ts. |
| T-04-04 | Tampering | applyHunkEdit concurrent writer | medium | mitigate | Re-read the file at save time; refuse with `stale` when the region no longer equals the buffer's original, so an agent's concurrent edit is never clobbered. |
| T-04-05 | Denial of Service | readHunkRegion on huge / binary files | low | mitigate | Binary and deleted files have no edit range (`hunkEditRange` → null). The buffer holds only the hunk's lines, capped in height. |
| T-04-SC | Tampering | npm/bun installs | low | accept | No package installs. |
</threat_model>
