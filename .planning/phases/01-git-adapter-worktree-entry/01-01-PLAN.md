# Plan 01-01: Typed git adapter + one resolver

Phase 1 · Git Adapter & Worktree Entry · tracer slice (packages/git + resolver + first consumer)

## Context

`packages/cli/src/git.ts` already holds the enumerated git helpers (abortable-ish `ProcessRunner`/`bunRunner`, `gitWorktreeList`, `gitWorktreeAdd`, `gitWorktreeRemove`, porcelain parsing, `gitDefaultBranch`, `gitCurrentBranch`, …), and `tk worktree create` resolves its path inline (`packages/cli/src/tk.ts` — `resolve(start, name)` inside the repo, then hand-gitignored). The design contract (`.agents/plans/2026-10-08-task-to-review.md`, §3) mandates: one typed adapter in `packages/git` (port of hunk's `hunk-vcs` runner + `hunk-git` commands), one resolver `resolveWorktreePath()` (port of gw's `ResolveWorktreePath`, `gw/internal/git/worktree.go`), inline logic deleted not wrapped.

Package conventions (`.planning/codebase/STRUCTURE.md`, `STACK.md`): `packages/<pkg>/{src,test}`, `@tasks/<pkg>` workspace dep, root `package.json` exports map entry `"./<pkg>"`, root `tsconfig.json` project reference, per-package `tsc` build; tests run from repo root with Bun's runner importing vitest API.

## Threat model

<threat_model>
ASVS level: 1 · Blocking threshold: high

- **[high] Argument/shell injection into git commands** — branch names, worktree names, ids, and paths originate from CLI argv and task metadata. Mitigation (in this plan): the adapter executes enumerated commands as argv arrays through `Bun.spawn` with no shell string interpolation; no command function builds a command line by string concatenation. Blocking: a finding of `sh -c`/shell-string git invocation in `packages/git` blocks the plan.
- **[high] Path traversal via worktree name or per-task override** — `../` in a name or a relative override could place a worktree outside the intended directory. Mitigation: `resolveWorktreePath` always returns a normalized absolute path (documented precedence); the caller (`tk worktree create`) rejects empty/whitespace names; the per-task override path (01-02) is resolved to absolute before use. Blocking: any resolver code path that returns a non-normalized or relative path blocks the plan.
- **[medium] Recorded-evidence spoofing** — worktree metadata could be recorded from caller-supplied values instead of actual git state. Mitigation: this plan records nothing yet (01-02 does); the resolver's purity rule (no writes, no state) plus 01-02's "record only from runner results" keep the branch-as-evidence invariant. Not blocking at L1.
- **[info] Secrets** — adapter handles no credentials; `.tasks/config.json` secret-redaction invariant (`urlEnv`) is untouched.
</threat_model>
