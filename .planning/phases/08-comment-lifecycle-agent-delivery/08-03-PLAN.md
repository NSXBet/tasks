<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → local web server | status and send POSTs from the island |
| stored comment text → DOM | bodies, authors, locations rendered in cards and the sent panel |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-08 | Tampering | `/threads/:tid/status` from the island | medium | mitigate | The island only sends `commentControls(...).to` values (open/resolved/dismissed); the server route already rejects anything else (400 on `sent`, tested). |
| T-08-09 | Tampering | double send | low | mitigate | The send button is disabled while a request is in flight and when nothing is open; the surface moves only `open` comments, so a repeat send is an empty batch with no write. |
| T-08-10 | Spoofing / XSS | sent-cards panel and pills | medium | mitigate | All comment-derived strings render as React text children; no `dangerouslySetInnerHTML` is added (grep check in Task 2 review). |
| T-08-11 | Information disclosure | browser bundle | low | mitigate | Only `@tasks/review/lifecycle` (type-only imports) is pulled at runtime; the bundle test asserts no storage code (`openStorage`, `withinTransaction`). |
</threat_model>
