# Phase 11 Plan 01: Chat stat card + report-cache fallback (PR-02, PR-03) Summary

**`tk finish`, the new `tk changes <id>` and `tk show` (fallback) report a task's changes as one counts-only stat card linking to the changes view: `Changes · <id>  1 commit · +1 −0 · 1 file  → <web>/tasks/<id>/diff · tk review <id>`. Finish now stamps a counts-only `metadata.report` cache, so when the branch is gone the card still shows the numbers, marked `stale — from finish report <at>`. No diff ever reaches chat output.**

**Commits withheld per AGENTS.md** (conservative profile: no git commit or push). All changes are uncommitted in the main tree. STATE.md and ROADMAP.md were not updated, per the orchestrator override.

## What changed

### Task 1 (tracer): finish → report stamp → stat card
- `packages/domain/src/changes-card.ts` (new, pure): types plus `statFromChangeset`, `readReportStat` (narrowing; non-negative integers only, else null), `changesLinks` (from `reviewDoors`, web + `/diff`), `statSummary`, `statCardLine`. Exported additively from domain `index.ts`.
- `packages/surface/src/operations/changes.ts` (new): `reportStampFor`, `resolveChanges`, `changesWire`. All git goes through `@tasks/git` (`deriveChangeset`, `gitBranchHead`); no spawn. Exported from surface `index.ts`.
- `finishIssueUow`: computes `reportStampFor(ctx, issue, runner, at)` before the save and merges `report` into the completion record (both branches). The doc comment now says finish stores a counts-only stamp and still never freezes.
- `events/derive.ts`: `'report'` added to `coveredMetadata()` (`// task.report (derived in 11-04)`); the header now says 11-04 derives `task.report` and `task.pr` there.
- `tk.ts` finish dispatch: `service.finish` + `seedFinishCursor` unchanged. The human-only `deriveChangeset` is replaced by `resolveChanges` on both paths; `--json` gets `changes`; `formatFinish(issue, view)` appends `\n` + dim card.

### Task 2: the ladder
`resolveChanges`: closed + frozen snapshot → `snapshot` (no git) → live → `report` (stale) → reopened snapshot (stale) → null. It is a read path with no writes.

### Task 3: `tk changes`, `tk show` fallback, help, contract text, docs
- `tk changes <id>` is read-only (not in `writers`): `{ id, changes }` JSON, `formatChanges` human (`no changes recorded` when null).
- `tk show`: only when live/frozen yields null and a report exists, `changeset` = `{source:"report", stale:true, counts:{additions,deletions}, commits, files}` and the human view shows a `CHANGES` section with the stat card.
- Help: HUMAN_HELP and HELP lines.
- Contract text: template step 4, both shipped SKILL.md copies (step 5), PRIME's review line. Then `tk skill install --force` and `tk onboard install` were run from source (`bun packages/cli/src/tk.ts …`) at the repo root, so the `.agents` copy (byte-identical to the CLI copy) and the AGENTS.md managed block were regenerated. `contract.test.ts` CONTRACT gained `"tk changes <id>"`.
- Docs: overview.md quick-start line plus a `### Changes and the stat card` section (format, links, JSON shape, ladder, the report stamp, the no-diff rule). architecture.md has a new `### Changes stat card path` section (the `metadata.report` stamp, the `resolveChanges` ladder, the silent wire key).
