2. Create `packages/surface/src/operations/commit.ts` with `commitWorktree(deps {cwd: string, transact, runner?}, id, message)`:
   a. Normalise the message. Strip C0/C1 controls except `\n` and `\t`, trim, and cap at 4000 chars. If it is empty, throw MessageError `commit message is empty`.

   e. Run `gitCommitTracked(worktree, msg)`.

|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-19 | Tampering | commit message as argv | high | mitigate | Argv arrays only. The message is passed as one `--message=<msg>` token, so a leading `-` cannot become a flag. Controls are stripped and length is capped. There is never a shell and never `--no-verify`/`--amend`. |
| T-11-20 | Tampering | committing the wrong tree | high | mitigate | The commit runs only in the recorded `metadata.worktree`. It refuses the main checkout, a missing worktree, and a branch mismatch. `--all` never adds untracked files. Tests assert each refusal makes no commit. |
| T-11-21 | Elevation of privilege | push from the commit button | medium | mitigate | The commit path has no push. Only `open pr` pushes, through the 11-02 prCreate (explicit, push before gh, idempotent). The tests' recorded argv asserts that commit never runs `push`. |
| T-11-22 | Spoofing | cross-site POST to the local web server | medium | accept | Same exposure as the existing `PUT /api/review/:id/file` and `/api/issue/*` writes. The server binds loopback and requires a JSON body, and a CSRF/Origin guard is a server-wide follow-up, not specific to these routes. |
| T-11-23 | Tampering | PR url injected into the page | low | mitigate | `readPrRecord` accepts only http(s) urls. The page escapes the url with `esc` and opens it with `rel="noopener noreferrer"`. |
</threat_model>
