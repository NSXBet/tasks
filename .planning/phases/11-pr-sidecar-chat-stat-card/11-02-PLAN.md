<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tk → gh / git subprocess | issue title/description and branch names become argv for `gh` and `git push` |
| gh stdout → record | PR number/url/state parsed from gh output are stored and later printed and linked |
| gh credentials | gh holds the user's GitHub token; tk must not read or echo it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-05 | Tampering | argv injection into gh (a title starting with `-`) | high | mitigate | Argv arrays only (no shell). Title and body use the `--title=<v>` / `--body=<v>` single-token form so a leading dash cannot become a flag. Branch and number come from the record or a validated int. |
| T-11-06 | Tampering | gh output stored as `metadata.pr` | medium | mitigate | `readPrRecord`/`normalizePrState` validate number (positive int), url (`https://` or `http://` only, so no `javascript:`) and state (enum). An invalid payload is a MessageError and nothing is saved. |
| T-11-07 | Information disclosure | gh stderr in error messages | medium | mitigate | Only the first stderr line is surfaced, with control characters stripped. tk never reads `GH_TOKEN`/`GITHUB_TOKEN` or passes env to logs. The fake gh in tests proves the code path needs no credentials. |
| T-11-08 | Denial of service | network calls inside a DB transaction | medium | mitigate | gh/git run outside `transact`; the save is a separate short transaction that re-reads the issue, so a hung gh never holds the store lock. |
| T-11-09 | Elevation of privilege | `TK_GH` override | low | accept | `TK_GH` runs a user-chosen binary with the user's own rights, the same trust as PATH. It is documented as a test/host override. |
| T-11-10 | Repudiation | duplicate PRs from re-runs | low | mitigate | Idempotent create: record refresh, else remote adoption by head branch, else create. Tests assert a single `pr create` across re-runs. |
</threat_model>
