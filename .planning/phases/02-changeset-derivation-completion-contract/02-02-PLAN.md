# Plan 02-02: Completion contract + terminal snapshot freeze

Phase 2 · Changeset Derivation & Completion Contract · FIN-01 + CHG-02 (tracer slice: tk finish end-to-end, then the close-time freeze)

## Context

02-01 delivered `deriveChangeset` (surface op over three enumerated `@tasks/git` commands) and show-side rendering. This plan completes the phase: `tk finish` is the single completion path into `ready-to-review` (FIN-01), and the close path freezes the terminal snapshot into `metadata["changeset"]` exactly once (CHG-02).

Existing machinery to reuse, not re-create: the CLI close path is `CommandService.mutate` (`packages/cli/src/tk.ts` ~411–418, close/reopen/set-state inside `transaction(this.database, …)`); the surface close path is `changeStatus` (`packages/surface/src/operations/mutate.ts` 104–119, `applyRunSideEffects` for startedAt/closedAt); the CLI dispatch/`--readonly` gate is the `writers` set (`tk.ts:36`, currently missing both `finish` and `work`); domain supplies the `StatusTransitionPolicy` interface + `transitionStatus` helper (`packages/domain/src/issue.ts:89–91`). Metadata is plain JsonValue — the freeze writes siblings next to Phase 1's `changeset.base` with no storage migration (D-04).

**Planner resolution — pattern-map decision point 1 (freeze call-site coverage):** tk has two write paths that both count as "the close path" (CLI `CommandService.mutate`, surface `changeStatus`). The freeze helper lands in surface's changeset operation module and is wired into BOTH paths; `closeMany` (`mutate.ts`, ~229) is inspected during the task and wired directly if it sets `closed` without funnelling through `changeStatus` (verify, don't assume). `todoDone` (CLI, ~487) also closes directly but only for branch-less todo tasks — derive-null means there is nothing to freeze, so no wiring there; exactly-once holds trivially. This is recorded so Phase 6's prune work inherits the full picture.
