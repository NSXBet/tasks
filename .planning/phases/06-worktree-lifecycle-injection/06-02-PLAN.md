<objective>
Make the lifecycle hooks and package-manager setup match LC-04 and the locked decisions. Hooks and install already run, but verification found these gaps:

1. Config key names: the spec and CONTEXT name `worktree.post_start` / `post_checkout` / `pre_end` / `install`, but `WorkspaceConfigSchema.worktree` is `.strict()` camelCase (`postStart`, `postCheckout`, `preEnd`, `pmSetup`). A config written to spec fails to parse, and every reader catches the error and falls back to `{}`, so all hooks are silently ignored.
2. `worktree.install: false` (locked by D) doesn't exist; only `pmSetup` does.
3. Lockfile precedence is pnpm → yarn → bun → npm. The locked order is bun → pnpm → yarn → npm.
4. `post_checkout` fires right alongside `post_start` on every creation, and never at any other point, so it isn't a separate lifecycle point at all. The schema doc comment says something different again ("after an existing worktree is entered again").
5. `tk worktree create <name> --branch <existing>` always passes `-b` and fails on an existing branch, so there's no checkout path for `post_checkout` to attach to.

Purpose: tk replaces gw's start/checkout/end hooks and its environment setup on start, with config that follows the spec.
Output: schema aliases + `install`, lockfile precedence, hook dispatch by lifecycle point, unit + e2e tests, docs.
</objective>
