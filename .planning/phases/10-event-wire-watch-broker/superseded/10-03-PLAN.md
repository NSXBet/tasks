Decision IDs: D-01 Broker, D-02 One stream, D-03 User messages — numbered in 10-01-PLAN.md `<objective>`. This plan
implements the agent half of D-01 (the pi/omp tool subscribes through the broker) and D-03's "the agent extension
surfaces them automatically".

**As an** agent working a task in pi/omp, **I want** review comments my reviewer sends, approvals, rejections and
plain comments on my tasks to arrive in my session on their own, **so that** the loop's step 11 ("picks up
automatically: comment → back to work; approval → merge worktree, close task") needs no polling and no tool call.

Purpose: ROADMAP Phase 10 SC-1 (many agents watch via tool calling) and SC-3 (comments, approvals and sent batches
picked up automatically). WIRE-01, WIRE-03.
Output: an inbox module, manager changes, index wiring, tests, docs and skill text.

  daemon transport (`useDaemon`, set from `TK_EVENTS === "daemon"` at index.ts:63) with fallback on daemon loss

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewer-authored text → agent prompt | comment bodies, authors and locations are injected into the agent session as followUp messages |
| task record metadata → follow decision | `metadata.worktree` / `metadata.agent_session` decide which tasks reach this session |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-09 | Tampering | comment text in followUp | medium | mitigate | `sanitize` strips ANSI/control characters and caps each field at 1000 chars; content is quoted as reviewer text with the author named. Delivering reviewer instructions to the agent is the feature (phase 8 D-03), so text is not otherwise filtered. |
| T-10-10 | Information disclosure | cross-session leakage | medium | mitigate | The inbox surfaces only followed tasks (touched ids, worktree containing cwd with a path-separator boundary check, exact session match); unrelated tasks' comments never reach the session. |
| T-10-11 | Denial of service | notification floods | low | mitigate | 300ms per-task coalescing into one message; 10-01 per-subscriber caps; manual watchers skip inbox kinds for followed tasks. |
| T-10-12 | Spoofing | echo of own actions | low | mitigate | Own comments recorded by id and dropped; only approved/rejected status moves are surfaced. |
</threat_model>
